# R768 诅咒卡火柴人图（9265 懊悔 / 9154 破绽 / 9185 麻痹 / 9252 代偿）

> 2026-11-16 · 店长口径三次修订：
> ① 初版「诅咒的图应该是交通标志风格的，你可以生成一个懊悔的火柴人标志」
> ② 退回初版「**只是要交通标志风格的火柴人，不是要交通标志！**」
>    —— 红环 / 白盘 / 斜杠 / 三角牌这些「牌子本身」是多余的，只要牌子上的那个象形小人。
> ③ 「白底不好看，换个颜色，比如紫色？你看看什么颜色适合」
> ④ 「**太深了这紫色，容易看不清**」→ 亮度回升一档（F → I），定稿后落地

---

## 一、两版差在哪（这是本轮唯一的设计教训）

| | v1（`regret_a/b/c`，已废弃） | v2（定稿路线） |
|---|---|---|
| 构图 | 一根交通标志牌：红环 + 白盘 + 红斜杠（或黄三角加黑框） | **只有象形火柴人**，没有牌子 |
| 背景 | 深紫 | 深紫（配色另议） |
| 结果 | 被退回 | 店长认可方向 |

教训记一条：**「某某风格」指的是方言，不是那个物件。** 说「交通标志风格的火柴人」，
要的是人们看交通标志时看到的那个**小人**（实心黑剪影、无五官、极简几何），
不是把整个标志牌搬过来。稿子里出现环、盘、斜杠、三角，就是把自己降级成了「图标复制品」。

修法也很直白：prompt 里加一句比喻 **「想象路牌上那个小黑人被单独剪下来、放在纯色背景上」**，
再显式禁掉 `red circle / white disc / diagonal slash / triangle / sign plate / border`。
这一句比喻比十行构图描述都管用。

- 黄闪电 = 麻痹的唯一识别点，必须在缩到 150px 时还看得见（所以写「粗、实心、尖端指向身体」）。

## 三、配色：底与图成对定，紫与亮要一起看

**这一条是本轮的技术核心，而且中途被实测推翻过一次判断。**

### 3.1 为什么不能只换底色

初版用「深紫底 `#1B1420` + 纯黑剪影」，实测**糊成一团**：
交通标志象形图的可读性来自「高明度底 + 低明度图」。白盘被换掉之后，
如果剪影仍是黑的，等于把唯一的对比关系一起换没了。
所以配色必须**成对**定，「底」和「图」是一件事。

### 3.2 店长两次口径

1. 「白底不好看，换个颜色，比如紫色？你看看什么颜色适合」→ 走「亮紫底 + 墨黑剪影」。
2. 定下 F（`#9A7BC4`）后：「**太深了这紫色，容易看不清**」→ 沿同一色相带把亮度往上推四档，
   「回升一档」定 **I**。

### 3.3 五档实测

| 档 | 底 | 剪影/底 | 石/底 | 电/底 | 结论 |
|---|---|---|---|---|---|
| F | `#9A7BC4` | 5.5:1 | 1.05 | 2.44 | 店长否掉：太深 |
| G | `#AE92D2` | 7.2:1 | 1.24 | 1.87 | 只亮一档，余地 |
| H | `#C2AAE0` | 9.3:1 | 1.60 | 1.45 | 我当时推荐 |
| **I** | **`#D5C2EE`** | **11.7:1** | 2.03 | 1.15 | **定稿**（店长：回升一档） |
| J | `#E6DBF6` | 14.5:1 | 2.51 | 1.08 | 基本是白，不用 |

### 3.4 被实测推翻的那条判断（必须记住）

我原本担心「底色一提亮，青裂缝 / 黄闪电 / 灰石头会被压掉」，所以在旧版 README 里
写过「一套四张里只要有一张靠彩色符号讲话，底色就必须压暗」。

量完才发现**方向搞错了**：

- 灰石 `#8C8C96` 与底色的对比在 F 档只有 **1.05:1**，到 J 档也只有 2.51 —— 全程都远低于 3:1。
- 黄电 `#FFD400` 更反直觉：F 档 2.44，越亮越低，J 档 1.08。

也就是说这些符号**从来不靠底色对比成立**，它们靠的是「符号 vs 黑色剪影」和自带的黑描边。
底色只管「剪影能不能跳出来」这一件事。所以底色可以放心提亮，三张卡的符号一张都不会受影响。

> 教训：判「符号会不会糊」要量**符号与它的实际相邻色**（这里是黑剪影），
> 不是量「符号与背景」。拿错参照物，结论会完全反过来。

## 四、验收口径

1. **主体必须落在可见带 y=68..335（高 268）内** —— `CardFace` 还会按 `CARD_ART_RATIO=0.662`
   再居中裁一次，超出的部分是真看不见。`_finish.py` 把主体缩到 250 高居中摆（y=77..327），
   落地脚本 `_apply_r768_palette.py` 会再核一次「非背景像素 bbox」，越界直接拒写。
   > 注意：`_recolor.py` 出的是**不透明实心图**（底色铺满），所以不能用 alpha 算 bbox
   > （那样结果永远是全图）。落地校验用的是「离角落底色 > 24 的像素」。
2. **卡图 448×404 满幅不透明**，与 9260/9261/9262 同规格。卡图靠**文件名 = 卡号**自动匹配
   （`assets/pics/<卡号>.png`），`cards.json` 的 `image` 字段保持空串，不用改。
3. 验收页 `_review/compare.html` 直接出**可见带**，不出整图 —— 拿整图看会漏掉被裁掉的部分。
4. 配色页 `recolor/schemes.html`、挑选图 `recolor/pick_all.png`、落地验收 `_review/band_pics.png`。
5. **图标类素材一律按目标显示尺寸判**：道具栏 `RelicBarLayout.CELL = 44.0`，
   所以猴爪 6066 要在 44px 下看（`tools/_r768_relic_row.py`），不能只看 128px 原图。
   实测 6066 不透明区 76×122、覆盖率 36%，与邻居 6065(32%) / 6067(31%) 齐平。

## 五、踩过的三个坑

1. **近黑噪点被判成「彩色元素」**：`_recolor.py` 初版用「饱和度 > 0.35 就原样保留」，
   而 (1,0,0) 这种压缩噪点饱和度是 1.0 —— 一提亮，剪影满身黑芝麻。
   改成「离底色和前景色都远（>60）才算第三种颜色」。**饱和度不是「有颜色」的可靠判据。**
2. **背景不是均匀的**：codex 出的底色中间比四边略亮几个单位，深色底下完全看不出，
   一旦重映射就浮出一块矩形补丁。修法：合图时画布铺满底色，只贴主体（软 mask 6→16）。
3. **代理预检不能用单一站点当探针**：原先拿 `chatgpt.com` 判，节点对它 SSL EOF 就红，
   但 `api.openai.com` 回 401（链路通）。改成依次试三个目标，任一拿到 HTTP 响应即算通。

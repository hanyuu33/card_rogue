02问题清单

按「观感收益 ÷ 改动风险」排序。每条的「风险」是相对你的回归基线（engine / reward / replay / smoke 四套）而言。

P0-1

字号失控：19 档取值，最细 8px

P0 最影响精致感 风险 低
证据
215 处字号设置点里出现 19 档取值；17 / 18 / 19 / 22 / 24 / 26 / 30 / 34 全部是只出现 1–5 次的孤值。仅 battle_scene.gd 一家就 83 处。卡面另有一套随缩放比派生的子阶：int(7*k) int(7.5*k) int(8*k) int(9*k) int(10*k) int(12*k)（见 card_face.gd:50/65/69/73/74/96/111/112）。
影响
同一层级的文字在不同界面大小不一致 → 玩家读不出「谁比谁更重要」→ 整体显得没做完。这是 19 档字号最贵的代价：不是难看，是层级失效。
做法
收敛为 7 档：12 / 14 / 16 / 20 / 24 / 32 / 48，游离值就近吸附（17→16、19→20、22→24、26→24、30→32、34→32）。卡面子阶单独定义常量，并把 int() 换成 roundi()——现在的 int(7.5*k) 在 k=1 时会被截成 7，视觉上比 8 档还小。
P0-2

颜色没有令牌：590 处字面量、280 种颜色，其中 111 种是「几乎同一个色」

P0 风险 中（分批）
证据
近重复聚类（RGB 欧氏距离 < 12）得到 44 簇。最典型的：暗底用了 7 种几乎同色——#14171F #17171F #171A24 #1A171F #1A1721 #1A1C26 #1B1C22；近白 5 种（#F0F0F0 #F2F2F2 #F5F2EA #F7F4EC #F7F5F0）；近浅蓝 4 种（#E0F7FF #E6FAFF #E8F6FF #EBFAFF）。
影响
① 改一次主题色要翻几十处，必然漏；② 同义不同色在画面上并置时会出现极轻微的「脏」——人眼说不出哪里不对，但会觉得不干净，这正是「不够精致」的常见来源。
做法
你已经有一个好底子：battle_scene.gd:37–84 里已有 35 条 COL_* 常量。把它抽成 scripts/ui_theme.gd（class_name UiTheme），补全成 5 组约 28 个令牌，然后用「每簇只留一个代表色」的方式把 280 种收敛到 ≤40 种。沿用你现有的常量习惯，不引入 .theme 资源，避免动到编辑器导入链。
P0-3

卡面：58×70 塞了 8 个元素，且缺图时正中是一整片白

P0 最拉分 风险 中
证据
card_face.gd:32–97 在 58×70（CARD_W/CARD_H，battle_scene.gd:16–17）里依次画：费用圆 → 名字 → 插图 → 种类 → 程速副行 → 字段行 → 力角标 → 生角标。art_for(id) 找不到 assets/pics/<id>.png 时返回 null，中部即留空——多数卡就是几乎全白的矩形。
影响
牌库、手牌、图鉴铺开时是一片白卡，这是单点最影响观感的问题；同时 8 个元素挤在 70px 高度里，才逼出了 7px 的文字。
做法
三步，按性价比：
① 无图回退（零素材、纯代码）：缺图时画按 kind 着色的淡底纹 + 大号首字水印（如「射」「盾」），把白洞填成有信息的色块；
② 补图：工程已有 assets/pics/<id>.png 的换皮契约（card_face.art_for），丢文件即生效，不需要改一行代码——这是接入文生图最省事的地方；
③ 战场小卡减元素：种类文字改用左侧 3px 色条；「程/速」与「字段」移到已有的悬停详情面板（battle_scene.gd:7162 _draw_info_panel）。腾出的竖向空间让最小字号从 7px 提到 ≥9px。
P1-1

一个视觉通道背了多重语义

P1 风险 低
证据
card_face.gd:42：frame = 红 if selected else card.rarity_color() —— 选中时稀有度信息直接消失，两个含义抢同一条 1.5px 边框。另外 #C1121F 同时出现在三个语义位：COL_HEALTH（生命，battle_scene.gd:72）、COL_WIN（胜利，:80）、以及选中描边。
影响
玩家无法同时读出「这张卡是什么稀有度」和「我选中了它」；红色既表示生命又表示胜利又表示选中，语义被稀释。
做法
选中态改成外发光 + 加粗描边（2.5px）+ 轻微上浮，不再占用边框颜色；#C1121F 专留给「生命/伤害」，胜利改用 #1B5E20（即现有的我方绿）。
P1-2

顶栏是固定像素布局，长文案会被右侧按钮压住

P1 风险 低 / 换容器则中
证据
scenes/battle.tscn 里所有节点都是硬编码 offset_left/right：StatusLabel 固定 480→790（310px 宽），而状态文案形如「鸭梨：受到 5 点伤害 → 最大生命 50 → 51（当前生命 5…」远超 310px，且没有截断策略。
影响
信息被静默切掉——玩家看不到战斗日志的关键后半句。
做法
最小改动：给该 Label 开 clip_text 或 text_overrun_behavior = TRIM_ELLIPSIS，先保证「不撞车」。彻底做法：换成 HBoxContainer（注意脚本里 $Toolbar/TurnLabel 之类的路径要同步改，属中等风险）。
P1-3

字体族声明复制了 14 份，且不内置字体

P1 风险 低
证据
13 个界面脚本各自 SystemFont.new() + font_names = ["Microsoft YaHei UI","Microsoft YaHei","SimHei"]（battle:252 / map:73 / deck_viewer:37 / event:283 / title:22,30 …），工程内 .ttf/.otf 数量为 0。
影响
① 换台机器、换系统版本，字形与字宽都会变（字宽变了，靠 get_string_size 手算的居中/折行就会偏移）；② 将来想统一换成更精致的字（如思源黑体）要改 14 处。
做法
短期抽 UiTheme.font() / UiTheme.font_bold()，14 处降为 1 处；中期把字体文件放进 assets/fonts/ 用 FontFile 加载，锁死跨机一致的度量——这对你「手算文字宽度」的绘制方式是实际收益，不只是审美。
P2-1

标题页：背景被 55% 白罩洗掉，漂浮卡背看起来像灰色占位块

P2 风险 低
证据
title_scene.gd:140–152：全屏铺 battle_bg.png 后盖一层 Color(1,1,1,0.55)；6 张卡背以 Color(0.25,0.28,0.38,0.14) 漂浮。
影响
背景美术基本看不见；卡背母题透明度 14%，在浅色底上退化成灰色方块——第一屏就给人「素材没加载」的错觉。
做法
白罩降到 ~0.30（或只压标题区域的局部渐隐）；卡背提到 ~0.28 并补 1px 描边，让它读得出「这是一张卡」。纯参数改动。
P2-2

两处文字对比度未过 WCAG AA

P2 风险 低
用途当前对比度建议改后
卡面·力量数值#B8860B on #FFF3.25:1#8A5F005.64:1
卡面·程速副行#777777 on #FFF4.48:1#6B6B6B5.33:1

其余配对（名字 21.0:1、生命 6.22:1、费用圆 7.12:1、四种「种类」色 5.3–8.6:1）均达标。但请把对比度当成下限而非目标——真正的问题是这两处同时还是全场最小的字号（8px / 12px），小字需要比 4.5:1 更高的余量。

P2-3

命名污染：坐标常量挂了颜色前缀

P2 风险 低
证据
map_scene.gd:18–19：COL_Y0 = 668.0、COL_DY = -96.0 是布局坐标，却与同文件 COL_LINE（颜色）共用 COL_ 前缀。
影响
「COL_ = 颜色」这个已经成立的约定被打破，后续谁看到 COL_Y0 都要愣一下。
做法
改名 LAYOUT_Y0 / LAYOUT_DY。

卡面为什么单独一套？卡面字号随卡牌缩放比 k 派生（战场 k=1、手牌 k=1.7、图鉴更大），这是合理的做法，不该动。要改的是两点：① 基阶从 6 档（7 / 7.5 / 8 / 9 / 10 / 12）收到 3 档（name 9 / value 12 / meta 9）；② int() → roundi()，避免 7.5 被截成 7。战场小卡同时按 P0-3 减少元素，让 meta 有机会从 7px 升到 9px。

间距 · 4px 基准

棋盘已经做对了（CELL=76、GRID_X/Y 是常量），但面板内侧距、按钮间距、文字行距仍是散落的数字（如 HAND_FAN_DROP=4.0 与 3.0 * CELL 同时存在）。建议补一档 SP_1..SP_6 = 4/8/12/16/24/32，只在新写与顺手改的地方用，不搞全量替换。

04落地批次

原则：每批都能独立验证、独立提交、独立回滚；每批结束跑一次 python _verify.py 对齐四套基线。

批 1低风险
见效快

纯参数与去重，几乎不可能出功能问题。

  • P2-2 两处对比度改为 #8A5F00 / #6B6B6B
  • P2-1 标题页白罩 0.55→0.30、卡背 0.14→0.28（+1px 描边）
  • P2-3 COL_Y0/COL_DY → LAYOUT_Y0/LAYOUT_DY
  • P1-3 新增 scripts/ui_theme.gd，提供 font() / font_bold()，把 14 处字体族声明收敛

验证：_verify.py 四套基线不变 + 用 title.tscn --screenshot 出图对比。

批 2中等
结构性

动到「层级」本身，收益最大。

  • P0-1 字号吸附到 7 档（215 处，按文件分批：先 battle_scene，再 map_scene，再其余）
  • 卡面子阶合并为 3 档 + int()→roundi()
  • P1-2 顶栏加 clip_text（先不动容器结构）
  • P1-1 选中态改「外发光 + 加粗描边」，边框色归还稀有度

验证：UI 层没有自动化断言，用你已有的 _probe_*.gd 探针跑绘制函数不崩 + --screenshot 出图人工比对。每改一个文件跑一次 --check-only。

批 3视觉主攻
2–3 轮

这一批才真正改变「看起来精致不精致」。

  • P0-3-① 卡面无图回退：按 kind 着色的淡底纹 + 首字水印（零素材，先消灭白洞）
  • P0-3-② 用文生图补高频卡的 assets/pics/<id>.png（丢文件即生效，零代码）
  • P0-3-③ 战场小卡减元素（种类→色条，程速/字段→悬停面板）
  • P0-2 颜色令牌化：把 280 种按簇吸附到 ≤40 种，battle_scene（356 处）最后做

验证：出图逐屏比对；颜色令牌化每完成一个文件就跑一次全量回归（GDScript 编译期就能抓出拼错的常量名）。

05明确不做

  • 不动引擎与数据。game_engine.gd / cards.json / run_state.gd 一行不改——界面体检不该牵动玩法。
  • 不动尺寸常量。CARD_W/CARD_H、CELL、GRID_X/Y、棋盘 6×3 都不碰：它们连着 AI 寻路、回放坐标、录像与冒烟测试。
  • 不引入 .theme 资源或第三方 UI 框架。令牌以 UiTheme 代码常量落地，避免动编辑器导入链与 .godot 缓存。
  • 不做全量美术重绘。补图只补高频出场卡，先跑通「回退底纹 + 补图」这套流水线再说。
  • 不顺手改文件行尾。改动沿用各文件现状（cards.json/battle_scene.gd/test_engine.gd 是 CRLF，card_data.gd/placement.gd/run_state.gd 是 LF），改完复核 count(b"\n") - count(b"\r\n") == 0。

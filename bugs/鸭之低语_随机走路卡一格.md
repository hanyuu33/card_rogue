# Bug 汇报：鸭之低语 · 随机走路在新地图只走一格

- **汇报时间**：2026-10-16
- **状态**：**已修复（R194，远端处理）**
- **严重度**：高（导致游戏无法进行）

## 现象
「鸭之低语」效果的随机走路逻辑，在新地图（rogue map）上只会移动 **1 格** 就停止，
导致受影响的单位 / 流程无法继续推进，游戏卡死、无法继续进行下去。

## 期望行为
随机走路应当持续前进，直到走到「一格**没走过的格子**」为止
（即遇到尚未访问过的格子才停下），而不是只走一格就结束。

## 复现步骤
1. 进入一张新地图（rogue map）。
2. 触发「鸭之低语」的随机走路效果。
3. 观察：单位仅移动 1 格即停止，后续流程无法推进。

## 备注
- 本汇报仅记录问题，**不做代码修复**，交由远端 / 后续处理。
- 相关逻辑所在：随机走路的「步数 / 终止条件」判定（应在走到未访问格子时终止，而非固定 1 格）。

# 处理记录（R194）

## 根因
`scripts/map_scene.gd` 的 `_start_whisper()` 只在 `_ready` 里挑一次路，并从
`RunState.available_nodes()` —— **含已经走过的邻居**（走过的房间可零消耗原路返回）——
的整池里随机抽一间，再用**一次性 Timer**（`_whisper_advance`）走一步：

| 抽中的目标 | `advance()` 的结果 | 后续 |
|---|---|---|
| 没走过的房间 | 扣 1 块巧克力 + 换场景（战斗 / 事件 / 商店 / 就地开奖励窗） | 回到地图时重跑 `_ready` → 再抽 → 链子接得上 |
| **走过的房间** | 只弹一句「什么都不会发生」，**不换场景** | 本场景**再也不会重跑 `_ready`** → 没人挑下一步 |

而 `_gui_input` 里有 `if _whisper_auto: return`（低语期间玩家点不动），
两者一叠加就是：**走到第二格时抽中旧房间 → 场景不重载 → 没人挑路 + 玩家点不动 = 卡死**。
玩家侧看到的就是「只移动 1 格就停止」。

## 修法
1. **挑路收进 `RunState.whisper_pick()`（唯一口）** —— 纯逻辑、可单测：
   - ① 隔壁就有没走过的 → 随机挑一间（走进就推进剧情）；
   - ② 隔壁全是走过的 → 朝**最近的没走过的房间**走一步（BFS 步数表），
     于是每一步都在**缩短**到未探索区域的距离，不会瞎逛、不会来回打转；
   - ③ 全图都走过了 → 任选一间邻居兜底，绝不把队伍钉死在原地。
2. **地图场景改成常驻循环**：`_process` → `_tick_whisper(delta)`，只要场景空闲
   （没在播进场过场 / 没开着奖励悬浮窗 / 还没入夜 / 非回放出图）就接着走下一步；
   走过旧房间只算「路过」（不扣巧克力、不切场景），一路走到「没走过的房间」为止。
3. 出图探针（`--screenshot`）钉住代走 —— 截图要可复现（与本工程「滚动类动画一律钉死」同款）。
4. 顺手把散落的字面量 `6010` 换成 `RunState.WHISPER_RELIC_ID`。

## 验证（R194）
- `test_engine.gd`：30 张地图全程模拟「挑路 → advance」——
  零次「挑不出下一间」、零次「有没走过的邻居却挑了走过的」、零次「没走近未探索区域」，
  且每张图都一路走到 Boss（最长 19 步）；另有「隔壁全是走过的 → 必须走近 1 步」单步断言、
  「全图走过 → 仍返回一间能走的邻居」兜底断言，以及 5 条源码守卫。
- `test_smoke.gd`：真场景两连测 ——
  ① 命运抽中「走过的房间」时仍会**接着挑下一步**（当年就是在这里静止）；
  ② **一连代走 3 步**到没走过的房间（旧实现走 1 步就停），路过步不扣巧克力。

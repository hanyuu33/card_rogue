# 安卓版打包说明

> Godot 4.3 卡牌肉鸽 Android APK 打包 + **签名一致性纪律**。
> 一句话：**两台设备必须用同一把签名钥匙**，否则同名包签名不同 → Android 拒绝覆盖安装。

---

## 〇、签名一致性纪律（打包前先读这节）

### 为什么会「签名不同、装不上」

Android 覆盖安装的硬条件：`package name`（`com.hanyuu.cardrogue`）相同 **且** 签名证书指纹相同。
只要两台设备各用各的 keystore，打出来的包指纹就不同，装新包时会报
`INSTALL_FAILED_UPDATE_INCOMPATIBLE`（应用未安装 / 签名不一致，提示「与已安装应用冲突」）。

本项目历史痛点：keystore 路径在
`C:/Android/debug.keystore` ↔ `%APPDATA%/Godot/keystores/debug.keystore` ↔ `AndroidDev/keys/release.keystore`
之间漂过多次，另一台机器还生成了自己的 `release.keystore`（PKCS12、密码未知），于是两台设备签名不一致。

### 三铁律

1. **唯一签名钥匙 = `release/keystore/debug.keystore`（已入库 git）**，指纹 SHA-256（去冒号小写）必须是：

   ```text
   59651c9b76e61240d1a1223a14635f658fe4d43f15020b3e44cfe22eec6e5baa
   ```

   别名 `androiddebugkey`、密码 `android`（Godot 官方模板钥匙，`CN=Godot, OU=Godot Engine, O=Stichting Godot, C=NL`，非机密）。
2. **打包必须走 `release/build_apk.sh`**。脚本会先校验 canonical 指纹，再把它同步到
   `C:/Android/debug.keystore`（`export_presets.cfg` 指向的固定路径）；本地钥匙签名漂了会当场拦截并替换回 canonical。
3. **打包后必验**：`apksigner verify --print-certs` 输出里
   `Signer #1 certificate SHA-256 digest` 必须等于上面那串指纹，否则这包作废、不得分发。

### 新设备怎么接上同一把签名

新设备（已 `git pull` 拿到仓库）直接：

```bash
bash release/build_apk.sh R<轮次>
```

脚本第 2 步会把 git 里的 canonical 钥匙同步到本机 `C:/Android/debug.keystore`，
之后导出的包签名与旧设备完全一致，可直接覆盖安装。

> ⚠️ 这是 **debug 签名钥匙**（密码公开、Godot 官方模板），只用于自用 / 内部分发。
> 将来若要上架 Google Play，需另生成正式 `release.keystore`（强密码、**不入库**、多处备份），
> 届时本节「唯一签名钥匙」要同步改写。

## 一、一键打包（推荐）

```bash
cd <项目目录>
bash release/build_apk.sh R534        # 归档为 dist/DuckCardsRogue_R534.apk
bash release/build_apk.sh             # 不归档，落成 dist/DuckCardsRogue.apk
```

脚本固定做 6 步（详见脚本头部注释）：工具自检 → 同步并校验 canonical 钥匙 → 清旧产物 →
headless 导出 → 签名（Godot 自动签不上就手动 `apksigner` 补签）→ 归档 + 验证指纹。
**两台设备都跑同一个脚本 = 同一把签名。**

## 三、手动打包（脚本失效时的备用，按顺序跑）

### 3.1 同步签名钥匙（关键，别跳过）

```bash
cp -f release/keystore/debug.keystore C:/Android/debug.keystore
```

### 3.2 校验指纹

```bash
export JAVA_HOME="$HOME/AndroidDev/jdk-17"
"$HOME/AndroidDev/jdk-17/bin/keytool.exe" -list -v -keystore C:/Android/debug.keystore \
  -storepass android -J-Duser.language=en 2>/dev/null | grep -i "SHA256:"
```

结果必须含 `59:65:1C:9B:76:E6:12:40:D1:A1:22:3A:14:63:5F:65:8F:E4:D4:3F:15:02:0B:3E:44:CF:E2:2E:EC:6E:5B:AA`。

### 3.3 导出

```bash
export JAVA_HOME="$HOME/AndroidDev/jdk-17"
"$HOME/.workbuddy/binaries/godot/Godot_v4.3-stable_win64_console.exe" \
  --headless --path . --export-release "Android" "dist/DuckCardsRogue.apk"
```

### 3.4 手动签名（Godot 自动签不上时才需要）

```bash
"$HOME/AndroidDev/android-sdk/build-tools/34.0.0/apksigner.bat" sign \
  --ks C:/Android/debug.keystore --ks-key-alias androiddebugkey \
  --ks-pass pass:android --key-pass pass:android \
  --in dist/DuckCardsRogue.apk --out dist/DuckCardsRogue-signed.apk
```

### 3.5 验证签名

```bash
"$HOME/AndroidDev/android-sdk/build-tools/34.0.0/apksigner.bat" verify -v dist/DuckCardsRogue-signed.apk
```

期望输出包含：

```text
Verified using v1 scheme (JAR signing): true
Verified using v2 scheme (APK Signature Scheme v2): true
Verified using v3 scheme (APK Signature Scheme v3): true
Number of signers: 1
```

## 四、项目导出预设

`export_presets.cfg` 中 `[preset.1] name="Android"` 关键选项：

- `export_path="dist/DuckCardsRogue.apk"`
- 架构：`armeabi-v7a=true`、`arm64-v8a=true`
- `package/unique_name="com.hanyuu.cardrogue"`
- `screen/immersive_mode=true`、渲染 `GL Compatibility`
- `keystore/debug` 与 `keystore/release` **都指向 `C:/Android/debug.keystore`**（别名 `androiddebugkey` / 密码 `android`）——这是「同一把签名」落地的关键，两台设备都指向这个固定路径。
- 图标（R189 补齐，4.3 正确键名见「七、已知问题」第 7 条）：
  - `launcher_icons/main_192x192` = `assets/ui/icon_android_legacy.png`（192×192）
  - `launcher_icons/adaptive_foreground_432x432` = `assets/ui/icon_android_fg.png`（432×432 透明，森林精魄头像）
  - `launcher_icons/adaptive_background_432x432` = `assets/ui/icon_android_bg.png`（432×432 径向渐变深林绿）
- 两个 preset 的 `exclude_filter` 已含 `*.keystore`（R538i 追加）——签名钥匙**不入包**。
- 触屏 / 返回键适配（R186）：见 `release/安卓优化方案.md`。

## 五、分发与归档

- 最终产物 `dist/DuckCardsRogue_R<轮次>.apk`。`dist/` 已写入 `.gitignore`，**包不入 git**，仅本机 / 网盘分发。
- **只留最新版 + 上一版**（用户口径，2026-10-24 起），更早的一律删，别把历史包攒成几 GB。
- 无后缀 `dist/DuckCardsRogue.apk` 是过渡产物，每次导出被覆盖，归档完成即删。
- 打包前先跑回归：`python _verify.py`。

## 六、桌面版（exe）打包

`export_presets.cfg` 的 `[preset.0] name="Windows Desktop"` 已设 `embed_pck=true`，单文件：

```bash
"$HOME/.workbuddy/binaries/godot/Godot_v4.3-stable_win64_console.exe" \
  --headless --path . --export-release "Windows Desktop" dist/DuckCardsRogue.exe
```

验收铁律（R477 复核）：
1. 必须把包拷到空目录再跑（留在仓库根会读到工作区 `cards.json`/`.godot`，假绿）。
2. 包内源码守卫一律「跳过」不是「失败」；**别拿「0 失败」当全绿**，要确认 `[跳过]` 计数不为 0（engine 597 / smoke 5）。
3. 单文件 exe 的 pck 在文件尾部：末 4 字节魔数 `GDPC`，pck 起点 = `len - 12 - pck_size`。

## 七、已知问题

1. **Godot 自动签名失败**：报 `All located 'apksigner' tools ... failed to execute`，根因是 headless 环境没设 `JAVA_HOME`。解决：`export JAVA_HOME="$HOME/AndroidDev/jdk-17"` 后再导出，或走 3.4 手动签名。
2. **旧 idsig 与新 APK 不匹配**：每次打包前删 `*.apk.idsig`。
3. **APK 内无独立 .pck**：Godot 4 安卓导出 `script_export_mode=2`，资源平铺进 `assets/`，双架构 `.so` 才是体积大头，属正常。
4. **导出预设 keystore 指向不存在的路径**：历史多次漂移（`release.keystore` / `%APPDATA%` 路径），现在统一指向 `C:/Android/debug.keystore`，见「〇、签名一致性纪律」。
5. **编辑器设置里的 Java/Android SDK 路径被清空**：`editor_settings-4.3.tres` 三项变空串，按 2.1 节写回即可。
6. **导出版资源判存（R190 修复）**：卡图判存必须用 `ResourceLoader.exists()`，不能用 `FileAccess.file_exists()`（导出包里无源 PNG，只有 `.ctex`，后者恒 false → 卡图不显示）。`card_face.gd` 是漏网之鱼，已改。
7. **安卓图标键名（R190 修复）**：4.3 用 `launcher_icons/*`（见第四节），旧键名 `package/icon*` 被静默忽略 → 图标回退成卡背。验收：解包后 `res/mipmap-xxxhdpi-v4/icon_foreground.png` 应与 `icon_android_fg.png` 像素一致。

### 包体守恒纪律（R350 事故后新增）

**根目录不许留 `_` 开头的 png 到出包那一刻。** Godot 的 import 不看 `.gitignore`，只看 `.gdignore`。

- 出图截图一律 `mv` 进 `art_src/_shots/`（在 `art_src/.gdignore` 覆盖范围内）。
- 两个 preset 的 `exclude_filter` 已含 `_*.png` 与 `*.keystore` 作闸。
- 出包后必查：APK 内 ctex 条数、`assets/cards.json` 等 JSON 逐字节一致、无 `_r*`/`_probe*` 残留。
- 体积构成（R350 基线，解压 204.4 MB）：native `.so` 130 MB / ctex 36.1 MB / 字体 15.2 MB / 音频 14.8 MB。
